# عزل فشل مهام التحليل - تقارير v0.9.4

## المشكلة التي عالجها الإصدار

كان الإصدار السابق يشغل أربعة أجزاء عميقة، ثم يعيد الجزء الفاشل بالحمولة نفسها أكثر من مرة. في الاختبار الحي نجحت 3 من 4، لكن الجزء الرابع استهلك نحو 73 ثانية و107 كيلوبايت موزعة قبل أن يعود بزر إعادة يدوي. هذا أثبت أن المشكلة ليست عطلًا عابرًا، بل مهمة كبيرة أو عقدًا غير مناسب.

## البنية الجديدة

تبقى واجهة التقدم بأربعة محاور تربوية:

1. القراءة التشخيصية.
2. الاستنتاجات التربوية.
3. التدخلات التنفيذية.
4. الجودة والمتابعة.

لكن التنفيذ الداخلي يبدأ بخمس مهام مستقلة:

- `diagnostic.full`
- `findings.full`
- `interventions.full`
- `governance.quality`
- `governance.monitoring`

لم تعد أدوات الجودة ودورة المتابعة تطلبان من Gemini داخل استجابة واحدة.

## علاج فشل المحتوى

إذا فشلت مهمة كاملة بسبب `MAX_TOKENS` أو JSON غير مكتمل:

- لا يعاد الطلب نفسه.
- تُقسم الأهداف إلى دفعات صغيرة.
- الاستنتاجات تقسم إلى 3 أهداف كحد أقصى لكل دفعة.
- التدخلات تقسم إلى هدفين لكل دفعة.
- القراءة التشخيصية تقسم إلى محورين لكل دفعة.

أما أخطاء الاتصال المؤقتة فقط فتحصل على إعادة واحدة محدودة مع احترام `Retry-After`.

## التشخيص الظاهر

تعيد Edge Function عند الفشل:

- اسم المهمة.
- المحور والنطاق.
- نوع الفشل.
- سبب كل محاولة.
- `finishReason`.
- حجم الحمولة والناتج.
- رموز الطلب والتفكير والإجابة عند توفرها.

ويعرض التطبيق اسم المهمة المتعثرة، مثل: `أدوات الجودة: توقف عند حد الإخراج`.

## ثوابت لا تتغير

- معادلات بوصلة الإتقان.
- الحسابات والرسوم المحلية.
- أعداد الاستنتاجات والتدخلات والمتابعة المقفلة.
- عدم إنشاء تقرير Gemini موازٍ.
- حفظ المهام الناجحة وعدم إعادتها.
