# نظام التقرير الرسمي المستقل

## المشكلة السابقة

كانت الطباعة تعتمد على `window.print()` للواجهة نفسها. أدى ذلك إلى:

- طباعة الـHero وشعار المرحلة والعبارات التسويقية.
- ظهور بطاقات Dashboard ومساحات فارغة ضخمة.
- انقسام الرسوم والجداول بين الصفحات.
- ظهور أشرطة تمرير أفقية داخل التقرير.
- تسرب مراجع تقنية مثل `metric:*` إلى القارئ النهائي.
- عدم وجود رأس تقرير رسمي أو تذييل وترقيم صفحات منضبط.

## القرار المعماري

واجهة التطبيق والتقرير الرسمي منتجان مختلفان:

```text
واجهة المراجعة والتحليل
        ↓
بيانات تقرير موحدة
        ↓
قالب A4 مستقل
        ↓
طباعة أو حفظ PDF
```

لا يستخدم التقرير عناصر DOM الخاصة بالـDashboard، ولا يعتمد على قواعد CSS الخاصة بالواجهة.

## الوحدة الجديدة

`assets/report-system.js`

وتوفر:

- `buildReportData(context)`
- `buildReportHtml(context, options)`
- `openReport(context, options)`

## عقد البيانات

تستقبل الوحدة نتيجة التحليل الحتمي ونتيجة Gemini ونوع الاستمارة وبيانات المصدر وجودة البيانات. ثم تنتج نسخة تقرير مختصرة ومهنية لا تعرض أكثر من:

- 4 مؤشرات رئيسة.
- 5 استنتاجات ذات أولوية.
- 5 إجراءات في خطة التحسين.
- 4 أدوات جودة.
- 4 قيود أو تنبيهات.

تبقى التفاصيل الكاملة داخل واجهة التطبيق وتصدير JSON.

## قواعد التقرير

- A4 بثلاث صفحات محددة.
- لا أزرار أو خطوات استخدام أو Hero.
- لا بطاقات دائرية كبيرة أو خلفيات باهتة.
- لا رموز تقنية داخل النص النهائي.
- لا جدول يتجاوز عرض الصفحة.
- لا استخدام لأداة جودة دون بيانات أو سبب ظاهر.
- لا عرض لكل الاستنتاجات المتكررة؛ تُنتقى النتائج الأعلى قيمة لاتخاذ القرار.
- التقرير العام لا يعرض أسماء الطلبة.

## الطباعة العرضية للواجهة

عند استخدام `Ctrl+P` داخل شاشة التطبيق، تُخفى الواجهة وتظهر رسالة تطلب استخدام زر «فتح التقرير الرسمي». يمنع ذلك الرجوع إلى المخرجات الطباعية القديمة بالخطأ.
