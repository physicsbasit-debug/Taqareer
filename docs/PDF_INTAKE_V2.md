# Document Intake v2 — PDF Canonical Structure Contract

## الهدف

طبقة `assets/pdf-intake-v2.js` تفصل **بنية صفحة PDF** عن **معناها التربوي**. لا تعرف هذه الطبقة أنواع تقارير تقارير، ولا أسماء المواد، ولا أسماء الملفات. مهمتها الوحيدة تحويل السطور المستخرجة من PDF.js إلى عقد موحد قبل التصنيف الدلالي.

## التدفق

```text
PDF.js text items
  ↓
Raw page lines
  ↓
Layout blocks
  ↓
CanonicalDocument 2.0.0
  ├─ metadata
  ├─ tables[]
  ├─ sections[]
  ├─ blocks[]
  ├─ unresolved[]
  └─ noise[]
  ↓
Semantic router / existing analyzers
```

## الثوابت

1. لا يدخل اسم الملف في قرار البنية.
2. لا توجد شروط `supervision_*` أو `student_work` أو أي نوع تقرير داخل قلب PDF Intake.
3. الترويسة والساعة ورقم الصفحة وعبارة الطباعة لا تصبح صفوف بيانات.
4. لا يُنشأ جدول إلا إذا ظهرت عناوين أعمدة مع صفوف متكررة قابلة للمطابقة.
5. كل Metadata معتمدة تحمل provenance: الصفحة، السطر، النص الأصلي، ودرجة الثقة.
6. أي كتلة غير مفهومة تبقى في `unresolved` بدل تحويلها قسرًا إلى خلية أو حذفها بصمت.
7. الصفوف الواقعة داخل جدول معتمد لا تُكرر داخل الأقسام السردية.

## الثقة

- `>= 0.85`: اعتماد بنيوي تلقائي.
- `0.60–0.84`: بنية تحتاج مراجعة.
- `< 0.60`: تبقى غير محسومة ولا تدخل كجدول معتمد.

## التوافق الخلفي

`document-lite.js` يشغّل المسارين أثناء القراءة:

- Canonical PDF Intake v2.
- المستخرج الجدولي القديم للمقارنة فقط.

إذا وجد v2 جدولًا معتمدًا يصبح هو المصدر الأساسي. إذا لم يجد أي جدول قابل للاستخدام يبقى المسار القديم fallback حتى لا تنكسر الملفات السابقة. تسجل `shadowComparison` عدد الصفوف والأعمدة في المسارين لاختبارات regression، ولا تسمح للمسار القديم بالكتابة فوق نتيجة v2.

## Quality Engine

لا تتغير قواعد جودة Excel/CSV/Word. في PDF، البيانات التي تصل إلى Quality Engine تأتي بعد الفصل البنيوي. لذلك لا تُحسب missing values أو duplicates على الترويسة أو التذييل؛ هذه الحسابات تخص الجدول المعتمد فقط. المستند السردي يبقى على مسار الجودة السردية الموجود أصلًا.

## معيار قبول المرحلة

- ملف المؤشرات الأحادي: Metadata صحيحة + جدول 13×2 + اتجاه المقياس غير مفترض.
- ملف إشرافي سردي: صفر جداول وهمية + أقسام سردية محفوظة + Metadata محفوظة.
- ملف dimension/measure مجهول النوع: يُستخرج بنيويًا من دون إضافة rule لنوع تقرير.
- لا يحتوي `pdf-intake-v2.js` على أسماء أنواع التقارير أو أسماء المواد أو filename switches.
- جميع اختبارات المشروع السابقة تبقى خضراء.
