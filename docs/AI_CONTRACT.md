# عقد الذكاء الاصطناعي v0.9.4

## المبدأ

التحليل الحتمي المتخصص هو مصدر الحسابات والأدلة والرسوم وبنية التقرير. Gemini يضيف قراءة تربوية عميقة وتحسينات تنفيذية مرتبطة بمعرفات موجودة فقط.

## العملية الإنتاجية

`enrich_segment`

## البروتوكول

`4.1.0`

## المحاور والمهام المعزولة

| المحور الأب | المهام الأولية |
|---|---|
| diagnostic | `diagnostic.full` |
| findings | `findings.full` |
| interventions | `interventions.full` |
| governance | `governance.quality` و`governance.monitoring` |

لا تشترك أدوات الجودة والمتابعة في استجابة واحدة. وإذا أخفقت مهمة محتوى كاملة بسبب القطع أو JSON غير صالح، لا يعاد الطلب نفسه؛ تُفكك المهمة حسب أهدافها إلى دفعات أصغر.

## شكل الرد

```json
{
  "contractVersion": "4.1.0",
  "segment": "findings",
  "taskId": "findings.batch.1",
  "scope": "findings",
  "deepAnalysisUnits": [],
  "patches": [],
  "additionalCautions": [],
  "missingDataRequests": []
}
```

## القيود

- كل `targetId` يجب أن يوجد في العقد المحلي.
- كل `field` يجب أن يكون مسموحًا لنوع الهدف.
- كل `evidenceRef` يجب أن يوجد في قائمة الأدلة.
- لا تغيير للأعداد أو النسب أو الفئات أو الرسوم.
- لا عناصر موازية ولا تدخلات أو مراحل متابعة إضافية.
- يسمح بالرد الفارغ إذا لم توجد إضافة ذات قيمة.

## الفشل والاستعادة

- `MAX_TOKENS` أو JSON التالف يشغل محاولة مختصرة واحدة داخل Edge Function للمهمة نفسها.
- إذا بقي فشل المحتوى، لا يعاد الطلب المطابق؛ تُقسم المهمة الكاملة إلى دفعات أهداف أصغر.
- الأخطاء المؤقتة فقط تحصل على إعادة واحدة محدودة مع احترام `Retry-After`.
- فشل مهمة لا يلغي المهام الناجحة.
- الواجهة تعرض اسم المهمة المتعثرة وسببها وعدد محاولاتها.
- الإعادة اليدوية تستهدف المهام الفاشلة وحدها مع الاحتفاظ بكل النتائج الناجحة.
