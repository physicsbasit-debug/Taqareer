# مدير الاستعادة الآلية لأجزاء التحليل - v0.9.3

## المشكلة

كان خط التحليل المقسّم يحفظ الأجزاء الناجحة، لكنه يتوقف بعد فشل الجزء ومحاولته المختصرة داخل Edge Function، ثم يطلب من المستخدم الضغط على زر الإعادة. إذا كان الخطأ مؤقتًا، قد يضطر المستخدم إلى الضغط أكثر من مرة.

## التصميم الجديد

```text
الأجزاء الأربعة بالتوازي
        ↓
نجاح الأجزاء السليمة وحفظها فورًا
        ↓
تصنيف فشل كل جزء: مؤقت أو غير قابل للإعادة
        ↓
جولة استعادة آلية 1 للمتعثر فقط
        ↓
جولة استعادة آلية 2 للمتعثر فقط عند الحاجة
        ↓
نجاح كامل، أو مصالحة جزئية بعد استنفاد الاستعادة
```

## سياسة الاستعادة

- الطلب الأول ليس محسوبًا ضمن جولتي الاستعادة.
- الحد الأقصى: جولتا استعادة آليتان لكل جزء.
- التأخير الافتراضي: نحو 0.9 ثانية ثم 2.4 ثانية، مع jitter بسيط.
- إذا أرسل الخادم `Retry-After` يلتزم المنسق بالمدة الأطول.
- الأجزاء الناجحة لا تعاد.
- النتيجة المرحلية تبقى معروضة أثناء الاستعادة.
- التخزين المؤقت لا يحفظ إلا النجاح.

## الأخطاء القابلة للإعادة

- انتهاء المهلة أو فشل الشبكة.
- 408 و429 وأخطاء 5xx المؤقتة.
- توقف الجزء عند حد الإخراج بعد المحاولة المختصرة.
- JSON غير صالح بعد المحاولة المختصرة.
- ضغط أو عدم توفر مؤقت من Gemini.

## الأخطاء غير القابلة للإعادة

- رمز الوصول غير صحيح.
- النطاق غير مسموح.
- رابط الوظيفة أو المفتاح العام غير مضبوط.
- حجم الطلب أكبر من الحد.
- العملية أو الجزء غير مدعوم.
- إعداد Gemini أو النموذج غير صالح.

## عقد الخطأ من Edge Function

تعيد الوظيفة عند الفشل:

```json
{
  "ok": false,
  "error": "...",
  "errorCode": "SEGMENT_OUTPUT_EXHAUSTED",
  "retryable": true,
  "operation": "enrich_segment",
  "segment": "governance"
}
```

## تجربة المستخدم

أثناء الاستعادة يظهر:

```text
اكتمل 3 من 4 · استعادة تلقائية 1/2 بعد لحظات: الجودة والمتابعة
```

وعند النجاح:

```text
استُعيد 1 جزء متعثر تلقائيًا دون تدخل منك.
```

لا يظهر زر الإعادة اليدوية إلا بعد استنفاد الاستعادة الآلية أو وجود خطأ غير قابل للإعادة.
