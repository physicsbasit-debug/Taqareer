# الاستعادة المعزولة للمهام - v0.9.4

> هذه الوثيقة تستبدل سياسة v0.9.3 التي كانت تعيد الجزء نفسه تلقائيًا أكثر من مرة.

## المبدأ الجديد

لا يُعاد فشل المحتوى بطلب مطابق. الاستعادة تعتمد على نوع الفشل:

| نوع الفشل | السلوك |
|---|---|
| مؤقت: شبكة، 408، 429، 5xx | إعادة واحدة محدودة للمهمة نفسها |
| محتوى: MAX_TOKENS أو JSON غير صالح | تفكيك المهمة الكاملة إلى دفعات أهداف أصغر |
| إعداد أو صلاحية: 401، CORS، نموذج غير صالح | توقف فوري ورسالة واضحة |

## الحفاظ على النجاح

- المهام الناجحة لا تعاد.
- المصالحة المرحلية لا تتراجع.
- الحسابات والرسوم لا تعاد.
- الإعادة اليدوية ترسل `failedTaskIds` فقط.
- الواجهة تعرض اسم المهمة والسبب والمحاولات بدل عبارة عامة عن جزء رابع مجهول.

## حد التزامن

يعمل المنسق بحد أقصى ثلاث مهام متزامنة لتقليل ضغط المعدل، بدل إطلاق جميع الطلبات الثقيلة معًا.

## مثال

```text
نجحت: diagnostic.full, interventions.full, governance.monitoring
فشلت: findings.full بسبب MAX_TOKENS
→ لا إعادة لـ findings.full نفسها
→ تشغيل findings.batch.1 و findings.batch.2
→ دمج كل دفعة ناجحة فورًا
```
