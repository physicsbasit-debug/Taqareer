# استقبال المستندات في تقارير

## Word DOCX

يقرأ التطبيق ملف `word/document.xml` محليًا، ثم يستخرج الجداول والفقرات السردية والترويسات. يبقى مسار Word مستقلًا ولم يتغير في v1.2.25.

## PDF النصي — Document Intake v2

عند فتح PDF يحمّل التطبيق PDF.js المثبت على الإصدار 6.2.108، ثم يمر المحتوى على طبقة بنيوية عامة قبل أي تصنيف تربوي:

1. استخراج عناصر النص وتجميعها في أسطر حسب الموضع.
2. تصنيف الأسطر إلى ترويسة وMetadata وعناوين أقسام وعناوين جداول وفقرات وتذييل وضجيج.
3. بناء `CanonicalDocument 2.0.0` يحفظ `metadata / tables / sections / unresolved / provenance`.
4. تمرير الجداول أو الأقسام النظيفة فقط إلى الـSemantic Router والمحللات الحالية.
5. تشغيل المسار الجدولي القديم في shadow mode للمقارنة، واستخدامه fallback فقط إذا لم يجد v2 بنية صالحة.

الطبقة البنيوية لا تحتوي أسماء أنواع تقارير ولا أسماء مواد ولا قواعد حسب اسم الملف. هدفها أن يظل اختلاف تنسيق PDF مشكلة Layout لا مشكلة Domain Adapter.

تفاصيل العقد: `docs/PDF_INTAKE_V2.md`.

## الصور وPDF الممسوح

إذا لم توجد طبقة نصية كافية، يبقى مسار القراءة البصرية الحالي كما هو. لا يغير v1.2.25 عقد Gemini أو Supabase.

## الخصوصية

- Word وExcel والصور تُقرأ داخل المتصفح أولًا.
- PDF.js يعمل داخل المتصفح، وDocument Intake v2 يعالج البنية محليًا.
- بيانات `طبع بواسطة` والتذييلات لا تدخل تلقائيًا إلى الجداول التحليلية.
- لا توجد أسرار أو SQL أو إعدادات Supabase جديدة في v1.2.25.
