# Phase 2-C Fix 5 — Network Transport & CORS Health Guard

الإصدار: `v1.1.5`  
وظيفة Edge: `V0.14.4`  
عقد التحليل: `6.6.0` دون تغيير.

## المشكلة

ظهر خطأ متصفح عام `Failed to fetch`. هذا الخطأ يحدث قبل وصول استجابة JSON مفهومة، وقد ينتج عن رابط وظيفة غير مكتمل، أو فشل CORS، أو انقطاع الشبكة، أو تعطل بوابة Edge. كانت الواجهة تعرض الربط بوصفه «جاهزًا» لمجرد وجود الرابط والمفتاح، ثم تسرب النص الإنجليزي الخام عند الفشل.

## العلاج

- إضافة عملية Edge خفيفة `health` لا تستدعي Gemini.
- فحص اتصال حي قبل إرسال التحليل المكلف، مع تخزين نتيجة الفحص لدقيقتين.
- إعادة محاولة فحص الشبكة مرة واحدة فقط، دون تكرار التحليل الأساسي تلقائيًا.
- تطبيع رابط Supabase تلقائيًا من رابط المشروع أو رابط لوحة التحكم إلى مسار الوظيفة الكامل.
- رفض الروابط غير الصحيحة قبل إجراء أي طلب شبكي.
- تطبيع `TAQAREER_ALLOWED_ORIGINS` إلى أصل URL، لذلك يقبل إعدادًا مثل رابط GitHub Pages الكامل الذي يحتوي `/Taqareer/`.
- إعادة CORS مقروءة حتى عند رفض النطاق بدل تحويل الخطأ إلى `Failed to fetch` غامض.
- شارة «جاهز» لا تظهر إلا بعد نجاح فحص Edge الحقيقي.
- تعريب أخطاء الشبكة ومنع تسريب `Failed to fetch` إلى المستخدم.

## المكتسبات المحفوظة

لم يتغير محرك الزيارات المتعددة، أو المقياس المعكوس، أو الرسوم، أو الصفوف 8–10، أو الخصوصية، أو حارس النطاق، أو الحارس العددي، أو التفكير المضبوط، أو مسار الإنقاذ، أو التحويل بين نماذج Gemini.
