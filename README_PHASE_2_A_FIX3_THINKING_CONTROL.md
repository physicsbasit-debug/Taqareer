# Phase 2-A Fix 3 — Controlled Thinking & MAX_TOKENS Rescue

## الإصدار

- التطبيق: `v1.0.3`
- Edge Function: `V0.13.3`
- عقد التحليل: `6.2.0`

## سبب الإصلاح

أثبت الاختبار الحي أن عقد القرار المضغوط في v1.0.2 ما زال قد ينتهي بـ`MAX_TOKENS`. السبب الجذري أن `gemini-3.5-flash` يستخدم مستوى تفكير افتراضيًا، بينما كان حد الإخراج 4600 فقط؛ فكان التفكير الداخلي وبنية JSON يتنافسان على السقف نفسه.

## العلاج

- ضبط التفكير الأساسي صراحة عند `low` بدل تركه على الوضع الافتراضي.
- رفع مساحة الاستجابة إلى 8192 دون مطالبة النموذج بإطالة النص.
- فرض `minItems` و`maxItems` داخل JSON Schema:
  - 2–3 وحدات تحليل.
  - 1–2 تدخلات.
  - 0–1 فحص منهجي.
- تقصير الحدود النصية ومنع القوائم المفرطة.
- قبول الاستجابة المكتملة حتى لو وصل `finishReason` إلى الحد، بشرط اجتياز التحقق.
- تشغيل مسار إنقاذ واحد فقط عند الاستجابة الناقصة:
  - `gemini-3.5-flash-lite`.
  - `thinkingLevel: minimal`.
  - 6144 رمزًا.
  - وحدتان تحليليتان وتدخل واحد.
- تسجيل رموز التفكير والإجابة في `serverTiming` لتشخيص أي حالة لاحقة.

## ما لم يتغير

- Gemini هو المحلل التربوي الأساسي.
- الحسابات والرسوم ومراجع الأدلة محلية ومحمية.
- لا تُعرض قوالب محلية بديلة بوصفها تحليلًا عميقًا.
- لا يوجد SQL أو سر جديد.
