# تقارير

منصة تحليل تربوي للدرجات والاستبانات والزيارات والبيانات التعليمية. الواجهة تعمل كموقع ثابت على GitHub Pages، بينما تبقى العمليات الحساسة والتحليل الخارجي في Supabase Edge Function.

## الحالة التشغيلية الحالية

- التطبيق: `v1.3.2`
- Browser CORS Contract: لا يرسل العميل أي رأس مخصص غير معلن في Edge؛ محاولات التحليل تبقى داخل العميل دون `x-taqareer-attempt`.
- Ranking Identity E2E: يعيد تركيب الاسم الكامل عندما تفصل PDF.js أصل الاسم والقبيلة بين band رقم الطالب وband القيد/الجنسية، ويثبت ترتيب الهوية بصيغة الاسم الأساسي أولًا ثم القبيلة في النهاية حتى جداول الأوائل في التقرير.
- Report Metadata: تقارير النتائج متعددة المواد تعرض «نوع المصدر» و«نطاق التحليل» بصورة مستقلة عن المادة المختارة.
- تخطيط التقرير: Cross-Section A4 Flow يستغل المساحة المتبقية بين الأقسام دون تصغير الخط أو كسر البطاقات.
- Supabase Edge: `V0.16.2`
- عقد التحليل: `6.6.0`
- Semantic Profile: `2.1.0`
- المصدر التشغيلي لوظيفة التحليل: `supabase/functions/analyze-educational-form/index.ts`
- Fix 16: محرك رسوم دلالي مشترك يختار شكل الرسم من الغرض التحليلي والبيانات، ويعمل على جميع أنواع التقارير بدل ربط كل تقرير بنوع رسم ثابت.
- Fix 29: مدخل PDF يثبت أعمدة الجداول من هندسة العناوين عبر جميع الصفحات، ويرفض أي جدول متكرر ناقص الصفحات بدل تحليل جزء صامت منه.
- Fix 30: يفصل التقرير الصف المحلل فعليًا عن نطاق صفوف المدرسة؛ `analyzedGrade` للعرض والتحليل و`schoolGradeRange` يبقى Metadata مدرسية مستقلة.
- PDF.js Multi-Subject: يثبت أعمدة المواد من أزواج `الدرجة/المستوى` بدل اشتراط تطابق موضع أجزاء عنوان المادة العربية، لضمان عمل كشف النتائج العريض في المتصفح الفعلي.
- Resilient Decision Core: ضغطة التحليل ترسل طلب Edge واحدًا؛ Gemini يبني نواة قرار مختصرة، والخادم يشتق منها التدخلات والمتابعة باستخدام الحسابات والأدلة الحتمية. وإذا تعذر المزود خارجيًا بعد المحاولتين المحدودتين، يكمل الخادم التقرير بقراءة محلية موثوقة بدل إيقاف المسار.
- Bounded AI: داخل Edge يوجد نموذج قرار أساسي وfallback واحد فقط كحد أقصى؛ لا action call ولا contract repair ولا segment rescue في المسار الأساسي. 429 توقف انتقال النماذج فورًا، ثم يُستخدم fallback محلي حتمي للتقرير إذا كان العطل مزوديًا لا إعدادًا خاطئًا.
- Score Payload: ملفات الدرجات ترسل إلى نواة القرار المؤشرات والرسوم فقط، بلا صفوف طلبة خام أو row evidence refs.
- Evidence Cache: النتيجة الناجحة تُعاد من cache محلي ببصمة الأدلة لمدة 24 ساعة (حتى 6 نتائج)، ويمكن تجاوزها صراحة عند إعادة التحليل.
- سياسة الرسوم المشتركة تدعم حاليًا: Bar, Histogram, 100% Stacked, Line, Radar, Bullet, Dumbbell, Scatter, Pareto, Box, Heatmap, Table.

لا تُحفظ نسخ نصية متسلسلة من Edge Function في جذر المستودع. تاريخ Git هو الأرشيف الرسمي للإصدارات القديمة.

## إعدادات نماذج Gemini الاختيارية

لا يلزم إضافة أي Secret جديد للنسخة الحالية. عند الحاجة مستقبلًا يمكن تغيير مسارات النماذج دون تعديل الكود عبر متغيرات اختيارية مفصولة بفواصل أو فاصلة منقوطة أو أسطر:

- `GEMINI_DECISION_MODEL` لنموذج نواة القرار الأساسي؛ الافتراضي `gemini-3.5-flash-lite`.
- `GEMINI_DECISION_FALLBACK_MODELS` لمرشح fallback واحد لنواة القرار؛ الافتراضي `gemini-3.6-flash`.
- `GEMINI_ANALYSIS_MODEL` و`GEMINI_REASONING_FALLBACK_MODELS` تبقى للمسارات/التوافق الأقدم ولا تتحكم في Decision Core الجديد ما لم يُعاد توصيلها صراحة.
- `GEMINI_FAST_MODEL` و`GEMINI_FAST_FALLBACK_MODELS` للمسارات السريعة الأخرى.
- `GEMINI_CLASSIFIER_FALLBACK_MODELS` للتصنيف الدلالي.
- `GEMINI_GENERAL_FALLBACK_MODELS` للاستخراج/المسارات العامة الأخرى.

تبقى القوائم الافتراضية الحالية مستخدمة بالكامل عند عدم ضبط هذه المتغيرات.

## بنية المستودع

```text
.github/        GitHub Actions وGitHub Pages
assets/         ملفات الواجهة ومحركات التحليل المحلية
scripts/        فحوص المشروع وصيانة المستودع
tests/          الاختبارات النشطة وFixtures اللازمة لها
supabase/       المصدر الحالي لوظائف Supabase
src-contracts/  عقود TypeScript المرجعية
docs/           الوثائق المعمارية الحالية
samples/        عينات تعليمية واختبارية
registry/       سجل أنواع الاستمارات
index.html      نقطة تشغيل الواجهة
manifest.json   عقد الإصدار والخصائص
```

## الفحص قبل أي رفع

```bash
npm ci
npm run check
```

يشمل الفحص:

- الاختبارات النشطة.
- سلامة JavaScript.
- عقود التحليل.
- مراجع الموقع الثابت.
- حارس نظافة المستودع لمنع عودة ملفات المراحل والحزم القديمة.

## سياسة المستودع

يبقى `main` للكود الحالي والاختبارات الحالية والوثائق الحالية فقط. ملفات الحزم المرحلية مثل `APPLY_*` و`TEST_REPORT_PHASE_*` و`CHANGED_FILES_MANIFEST*` ونسخ `SUPABASE_FUNCTION_GEMINI_V*.txt` تُحفظ خارج المستودع داخل حزم التسليم فقط.

## النشر

راجع `docs/DEPLOYMENT.md` للتفاصيل. GitHub Pages ينشر ملفات التشغيل العامة فقط (`index.html` و`manifest.json` و`assets/`) ولا ينشر وثائق التطوير أو العينات أو ملفات الخادم.
