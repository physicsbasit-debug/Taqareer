# تقارير v0.6.0

## Phase 1-B2: نظام التقرير الرسمي المستقل

تعالج هذه النسخة جذر مشكلة الطباعة السابقة. لم يعد التطبيق يطبع واجهة النتائج أو الـDashboard، بل ينشئ مستندًا رسميًا مستقلًا بمقاس A4، له بنية وهوية وقواعد طباعة خاصة به.

## ما تغير جذريًا

- إضافة وحدة مستقلة: `assets/report-system.js`.
- فصل واجهة المراجعة التفاعلية عن التقرير الرسمي المطبوع.
- استبدال زر «طباعة النتائج» بزر «فتح التقرير الرسمي».
- إنشاء تقرير من ثلاث صفحات منظمة:
  1. الهوية والملخص التنفيذي والمؤشرات والرسم.
  2. الاستنتاجات الرئيسة وأدلتها وآثارها التربوية.
  3. خطة التحسين وأدوات الجودة وحدود التحليل وإعادة القياس.
- منع طباعة واجهة التطبيق مباشرة عبر `Ctrl+P`، مع توجيه المستخدم إلى التقرير الرسمي.
- تحويل مراجع الأدلة التقنية مثل `metric:masteryPct` و`line:12` إلى صياغة بشرية مفهومة.
- ترجمة أسماء أدوات الجودة الإنجليزية إلى تسميات عربية مناسبة.
- إزالة أزرار الواجهة، شريط الخطوات، الرسائل الدعائية، البطاقات الضخمة، وأشرطة التمرير من التقرير.
- وضع جدول خطة التحسين داخل عرض A4 دون تمرير أفقي.
- إضافة رقم مرجعي وتاريخ وهوية ثابتة وتذييل وترقيم صفحات واضح.

## طريقة الاستخدام

1. ارفع الملف ونفّذ التحليل كالمعتاد.
2. في شاشة النتائج اضغط **فتح التقرير الرسمي**.
3. راجع التقرير في نافذة مستقلة.
4. اضغط **طباعة التقرير أو حفظه PDF**.

## الرفع فوق المستودع الحالي

استخدم حزمة `changed_files_only`. لا تحتوي على `.github` أو `.nojekyll`، ولذلك لا تمس Workflow الذي أنشأته يدويًا.

لا يلزم تعديل وظيفة Supabase أو أسرار Gemini في هذه المرحلة.
